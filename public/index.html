🧪 原型试用受理台
总入口 受理 / 派出 试用终端 领报酬 审核 / 重启复查

相似结束页，不等于亲自找到入口。

这里把委托人任务、事前计件约定、试用员身份、签发原型版本、逐步点击轨迹、 提示泄题记录、招募方审核和一次完成只付一次的报酬台账放在同一套本地持久化服务中。

① 本地受理与派出 ② 试用员点击 ③ 领取报酬 ④ 重启后复查
1

受理 / 发包

委托人登记任务与提示；招募方按泄题键检查任务包，并向指定试用员真正发出邀约。
2

试用终端

只显示当前画面、当前可点动作和任务步骤状态；每个点击由服务端状态机生效。
3

领报酬

按接单时保存的三点或两点约定支付；多设备重传同一 completionId 不重复发薪。
4

审核 / 复查

查看精确目标、重放错误、设计师捷径、代点来源、此前提示回条和结算台账。

本题的判定红线

  • “收藏蓝册 → 取消收藏蓝册”必须是签发原型上两个有序、真实改状态的事件。
  • 第二个动作改绑另一本册，即使出现外观键相同的结束页，也会因目标不一致失败。
  • 服务端只认 actionId + targetId + screenId + version，不认同名“确定”。
  • 此前同一身份实际看过排除提示，受理服务会读回原领取回条；本次不临时提示也排除发现奖。
  • 互不泄题的红册待借任务仍可正常接做、审核和领酬。

命令行入口

npm start
# 默认地址 http://127.0.0.1:4173
# 数据文件 data/local-db.json

npm run verify
# 自动跑通：独立三点、错目标失败、
# 旧提示回条排除、不泄题任务得酬、
# 多设备并发重传、停服重启复查。

npm test
# 纯领域规则测试。

所有数据均在本地；无需真实网站或外部服务。
