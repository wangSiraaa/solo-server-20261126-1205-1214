# 桥下书店 · 连载共读服务

一个社区书店的**连载共读**后端。作者交来带岔路、回合点和多个结尾的短篇；同一件事
可以在不同章节揭晓。服务按读者**实际读到的情节**组织共读——而不是比较书名和最后一页。

只用 Python 标准库，无需安装依赖。提供 HTTP/JSON 接口与一个可重启复查的本地演示。

---

## 快速开始

```bash
# 运行全部测试（23 个领域测试 + 2 个 HTTP 测试）
python3 -m unittest discover -s tests -v

# 跑一遍完整演示（每次重置到干净状态）
python3 -m bookclub.demo

# 从磁盘状态重启并只读复查（模拟进程重启）
python3 -m bookclub.demo --keep --review

# 启动常驻 HTTP 服务（默认 127.0.0.1:8099，可接 --state 落盘）
python3 -m bookclub.api --port 8099 --state /tmp/bookclub.json
```

演示会驱动真实 HTTP 入口（`urllib` 调本地服务），因此走的就是书店前台会调用的代码路径。

## 核心模型

| 概念 | 含义 |
|------|------|
| **作品 (work)** | 作者的短篇，可发布多个**版本 (turn)**。 |
| **段 (segment)** | 版本里的一节文字。可 `discloses`（读过即得事实）、`requires`（进入前必须已得事实）、`describes`（结构上的互相引用，**不产生事实**）。 |
| **事实 (fact)** | 情节中的一条揭晓，如“钥匙藏在桥下”。按 `id` 匹配，**绝不按段标题或末页**。 |
| **阅读记录** | 按 `(读者, 事实, 版本)` 记录“读者真正读完、并从哪一段得到此事实”。 |
| **场次 (session)** | `served`（会前备稿锁稿）或 `open`（可中途汇入）。可指定 `goals`（要一起到达的汇合段/末段）。 |
| **补读 (practice)** | 为缺一条事实的读者开的一小段补读，钉死版本与段。 |
| **改约 (rebook)** | 无法在本场补上（该版本根本没有揭晓，或店员时段冲突）时，另约时间/场次。 |

### 几条关键规则

1. **事实跨版本不自动继承。** 编辑发布新版本时必须显式声明旧段的哪些事实仍成立
   （`unchanged_segments` 按段声明，或 `carry_facts` 按事实声明）。否则同一事实在新
   版本需重新读到。
2. **按段声明是精确的。** 若“钥匙在桥下”的揭晓从 `ch2b` 挪到后一段 `ch2c`，即便
   把 `ch2b` 标为“未改”，那条**被挪走的**事实也不会跟过去——只有当引用的旧段在新版
   中仍然揭晓该事实时，才算继承。
3. **未读完的误点不算数。** `revoke` 只会缩小权限；撤掉一条从未真正读完的记录后，
   读者必须真的去读来源段才能再进后续段落。任何“凭空生成揭晓”的路径都不存在。
4. **循环互引不产生事实。** `describes` 仅是结构元数据；甲引乙、乙引甲也读不出一条
   谁都没揭晓的真想。
5. **两条同名支线各自揭晓同一事实。** 两人分别走甲(信)、乙(录音)取得“钥匙在桥下”，
   都允许进入需要该事实的末段——无论是各自先读后合场，还是会中汇入。
6. **会前备稿锁一条连续领读路线。** 领读按“同一条路线”把全组带向汇合段；每位听众
   只吸收自己满足前置条件的那部分事实。
7. **店员时段是硬约束。** 同一个店员不能同时领两场**时间重叠**的场次；读者事实一字
   未改也必须改约。前台判定把“事实问题（补读）”和“排期问题（改约）”分开回答。
8. **补读会留存。** 补读完成后，读者在该版本上真正具备该事实，参加下一场可以直接沿用。

## HTTP 接口

所有操作都有程序入口。路径参数支持中文（URL 解码）。

### 创作 / 发布
| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/facts` | 定义一个事实 `{id, description}` |
| POST | `/works` | 定义作品 `{id, title}` |
| POST | `/works/{wid}/turns` | 发布版本 `{label, segments, revision_of?, unchanged_segments?, carry_facts?}` |
| GET | `/works/{wid}` · `/turns/{tid}` | 查看作品/版本 |
| POST | `/turns/{tid}/revert` | 将作品现行版还原到该版本（不改动任何阅读记录） |

### 报名 / 场次
| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/sessions` | 登记场次 `{title, work, kind, turn?, goals?}` |
| GET | `/sessions/{sid}` · `/sessions/{sid}/state` | 查看场次（含锁定领读稿、改约请求） |
| POST | `/sessions/{sid}/register` | 读者报名 `{reader}` |
| POST | `/sessions/{sid}/serve` | 开读：锁版本、算菜单/领读路线、可占用店员时段 `{staff?, start?, end?}` |
| POST | `/sessions/{sid}/lock` | 锁稿（`served` 场次） |
| POST | `/sessions/{sid}/join` | 中途汇入（`open` 场次）`{reader, hold_facts?}`，返回汇合点 |

### 阅读 / 事实
| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/read` | 读者真正读完一段 `{reader, work, turn, segment}`（不满足 `requires` 返回 409） |
| POST | `/revoke` | 撤去某条阅读记录（缩小权限） |
| GET | `/readers/{rid}` | 读者全部事实与来源 |
| GET | `/turns/{tid}/can-enter?reader=&segment=` | 该读者此刻能否进入某段 |
| POST | `/turns/{tid}/simulate-read` | 不落盘地预演一次阅读 |
| POST | `/compare-intake` | 从同一受理点比较两版本下的事实状态 `{reader, fact, turn_a, turn_b, segment?}` |

### 补读 / 改约 / 前台
| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/sessions/{sid}/assess` | 判定 `has` / `catch_up` / `rebook` |
| POST | `/practices` | 开补读 `{reader, session, fact, turn?}`（无来源时 409 `needs_rebook`） |
| POST | `/practices/{pid}/complete` | 完成补读，事实记入对应版本 |
| GET | `/practices/{pid}/facts` | 该读者经补读获得的事实（按版本） |
| POST | `/sessions/{sid}/front-desk` | 前台综合判定：区分该补读还是该改约 `{reader, fact, staff?, start?, end?, turn?}` |
| POST | `/sessions/{sid}/rebook` · GET `/sessions/{sid}/requests` | 记录/查看改约请求 |

### 其他
`GET /plan?reader=&work=&turn=` 给出单读者的最短补读路线；`GET /snapshot` 导出全量状态；
`GET /health` 健康检查。错误统一为 `{"error": {"code", "message", ...}}` 并映射到合适的
HTTP 状态码（400/404/405/409/500）。

## 演示剧情（六段）

作品《桥下的钥匙》初版六段：

```
ch1 一·雨夜归人 ─┬─ ch2a 二·桥下(信)    → discloses: 钥匙在桥下, 信封上的名字
                 └─ ch2b 二·桥下(录音)  → discloses: 钥匙在桥下, 磁带里的忏悔
                        （两段同名同义，靠事实 id 而非标题匹配）
                              │
                            ch3 三·天亮之前  (requires: 钥匙在桥下)
                              │
                   ┌──────────┴──────────┐
                e1 结局·重逢           e2 结局·空屋
             (requires: 钥匙在桥下)  (requires: 钥匙在桥下)
```

演示按题述逐步走：

1. 阿禾读**信**支、阿岚读**录音**支，各自获得“钥匙在桥下”。
2. 会前备稿、锁一条连续领读路线 `[e1, …]`，两人都能进末段。
3. **第一遍比较**（新场尚未锁稿的受理点）：发布 v2，把录音的揭晓挪到后一段 → 阿岚暂
   时进不了末段，阿禾不受影响（因信支被声明“未改”）。
4. **第二遍比较**（相同起点）：还原 v1，只撤去阿岚先前误点、从未读完的记录 → 阿岚再
   次暂时进不了末段；绕过前置直接进末段被拒（409）。
5. 阿岚真正补读后，两人都具备事实；接一笔要两人一起开读的新场：唯一能领末段的店员
   时段重叠 → 即使读者事实一字未改也必须**改约**。前台明确区分“补读 / 改约”。
6. 补读完成后，参加下一场可直接沿用（下一场锁 v2，阿岚经补读即 `has`）。

`--review` 会从磁盘重启，只读打印版本、每人事实来源、场次领读路线与补读记录。

## 设计取舍

* **按 `(读者, 事实, 版本)` 记账**是本服务的核心。它同时满足“两条路揭晓同一件事”“改版
  可能把揭晓挪到下一段”“同名不同结局”等要求，而无需比较书名或末页。
* **版本继承是显式且按段精确的。** 这避免“改版后旧读悄悄算数”，也避免“一改版全部作废”。
* **菜单与领读路线是目标导向的**（围绕场次 `goals`），因此中途汇入能找到真实汇合点，
  而不只是求可读段落的交集。
* **补读与改约分开：** 事实问题能补则补（开一小段补读），排期问题只能改约。前台
  `front-desk` 一次回答两者。
* **落盘使用带重试的就地回退**，以适配本环境 `virtiofs` 偶发的 `rename` 失败；单写者
  加锁，保证一致。
