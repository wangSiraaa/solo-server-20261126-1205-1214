# 胶片照相馆本地接件放样后端

把一张相纸划成很小的格子，底片每拍投在各格上的光量由店里上传；**同一张纸已经吃进去的光不能擦掉**。
系统根据阶梯样卡把累计光量区间对应到肉眼色阶，接住顾客圈选的"必保脸 / 可加深背景 / 可接受色阶"，
在现有片材与现场拍数预算内排出**可供师傅照做的洗印单**，并把曝光回条、新样、成品领取全部落账。

只依赖 Python 3.11 标准库（含 SQLite），无需联网、无需第三方包。

## 选型：固定遮片暗房

题目给了两种暗房，本实现选择**固定遮片**：

- 开批前按有限**片材预算**刻制若干通光格形状，批次内重复使用；
- **开工后不再补刻**，一张片能翻动到哪些位置，全部以**备料登记表**为准；
- 每一拍 = 选一张已登记遮片 + 放到一个已登记偏移位置，开孔格透光、其余格不动。

选手工遮挡店时，本设计的对应关系（业务流程完全相同，只需替换排程器）：

| 固定遮片（已实现） | 手工遮挡（映射） |
| --- | --- |
| 开批前刻制遮片形状 | 店里已有挡板台账（不可新增） |
| 遮片翻动位置登记 | 现场操作时段分配到各张纸 |
| 开工后补刻被拒 | 操作时段一过，只能沿用当时遮挡 |
| 每拍按洗印单核对遮片/位置 | 每拍须有师傅站台才可移动挡板 |

两种暗房共用：业务端开单 → 师傅确认实际曝光 → 接回新样 → 凭订单领取成品；
**曝光回条迟到不能把同一张纸当成新纸再曝光。**

## 核心不变量

1. **光量单调累加**：`paper.accumulated_json` 只由曝光回条做加法更新，代码中没有任何清零/回退路径；
2. **同纸同拍唯一**：`shot_log` 对 `(paper_id, seq)` 建唯一约束，重复/迟到回条返回 409；
3. **遮片登记冻结**：批次离开 `intake` 状态后，任何 `register_mask` 都被数据库上层拒绝；
4. **拍法必须用已登记遮片**：回条核对洗印单，并校验遮片形状+偏移在备料登记表上；
5. **状态持久化**：全部状态在本地 SQLite，进程重开后原样接回。

## 色阶与圈选语义

阶梯样卡 `[(阶名, 起始光量), ...]`：阶 *k* 覆盖 `[lower_k, lower_{k+1})`，末阶上无界。

- **脸（必须保住）**：最终累计光量只能停在指定色阶自己的区间内，不接受滑到更深阶；
  起点已超出该区间即硬性不可行（光擦不掉）。
- **背景（可以加深）**：至少达到目标阶起始量，目标阶及其更深的光量都接受。
- 未圈选的格子不设约束（随遮片开孔自然受光）。

## 排程器（`photolab/planner.py`，纯函数）

- 枚举纸面全部非空通光格子集（格子多时退化为单格/整行/整列/整版/相邻对形状族）；
- 规范化形状并枚举每个形状可翻动的合规偏移（开孔不得越出纸面）；
- 逐拍深度优先搜索，带三条剪枝：某格顶出允许上界、剩余拍数够不到目标下限、预算耗尽；
- 多重集去重后按拍数排序；整批合并去重遮片形状，核对片材预算与总拍数。

## 工作流与 HTTP 接口

```
POST /batches                     业务端开单（纸、起点光量、每拍透光量、圈选、旧试印沿用数）
POST /batches/{id}/prepare        备料：排程验证；可行则刻片并登记全部可翻动位置（不可行 422 带原因）
POST /batches/{id}/open           下洗印单（遮片冻结，逐纸写清每拍遮片/偏移/透光格/光量）
GET  /batches/{id}/print-sheet    师傅取洗印单
POST /papers/{id}/shots           师傅确认一拍曝光（服务端按单核对；重复/迟到回条 409）
POST /papers/{id}/samples         接回新样（按累计光量推算实际成色阶）
POST /orders/{id}/deliver         凭订单领取真正洗出的成品
GET  /batches/{id}/status         批次/纸/累计光量/流水查询
POST /stock/trials                登记已付费旧试印库存
```

成品用**整数色阶渲染小图**代替真实显影：每批输出 SVG（带格子与色阶序号）和 PGM（P5 位图）。

## 验收场景（`tests/` 与 `demo/http_demo.py`）

以两个相邻格（1×2）做最小生意，样卡 `阶二@光量2、阶三@光量3`，各格每拍透一：

1. **可交件**：脸累计 2、背景累计 1，脸保阶二、背景做阶三，预算两拍。
   排程结果**恰好一种操作**：单格遮片翻到背景格，照两拍，最终 `{脸:2, 背景:3}`。
2. **只换样卡**：背景目标阶改为从光量 4 开始，现场仍只剩两拍 → 备料 422，
   原因"2 拍后最多 3，到不了阶三起始光量 4"，**不能交**。
3. **恢复原样卡，仅把脸改成累计 3（已越过阶二）** → 备料 422，
   原因"已吃进去的光不能擦掉"，**不能交**。
4. **程序重开后接另一张起点不同的纸**（背景从 0 起步，预算三拍）：
   关闭并重建服务后，新批次算出只照背景三拍，累计 `{脸:2, 背景:3}`。
5. 迟到的第三拍回条 → 409，同一张纸不会被当新纸再曝光；重复提交同拍同样被唯一约束挡住。
6. 开工后补刻遮片 → 409；回条光量与洗印单不符 → 409 且不留账。
7. 沿用已付费旧试印：库存占用、零新曝光、直接凭单取件；库存不足开单即拒。
